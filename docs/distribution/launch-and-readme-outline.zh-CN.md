# 引流与简要 README 草案

2026-10-03。首要目标：让有相应需求的人看清项目的实际用途，能够开始使用，并愿意继续用。下载与 GitHub 关注是次要结果。当前仅构思和本地提交，尚未对外发布。

普通用户的下载、安装与首次使用步骤见[从零安装路线](first-install-route.zh-CN.md)；该文区分旧公开包与待发布免驱版，并列出交付缺口。

## 先证明用途

用户个人经常使用的三项功能是：实时看额度、看 Agent 进度、快速调节模型。这三项实际需求作为介绍和演示的主线；手柄与小键盘是使用这些能力的操作形式。

| 需求 | 演示应证明什么 | README 要回答什么 |
| --- | --- | --- |
| 实时看额度 | 额度在面板中可见，并按当前实现刷新 | 显示哪些额度窗口、何时更新，读取失败时如何表现 |
| 看 Agent 进度 | 看到任务的运行、完成或等待处理状态，并进入对应任务 | 能看到哪些状态、如何识别需要自己处理的任务 |
| 快速调节模型 | 显示切换前后模型，直接完成一次切换 | 支持哪些选择、作用于哪个任务，以及何时生效 |

首要受众是经常使用 Codex、需要反复查看额度和多个任务状态、按任务调整模型的人。具体推荐哪个产品，再依据其使用习惯和是否有手柄判断。每个仓库只展示自身当前发行版确实提供的能力，不能把另一产品的功能直接算入。

候选首句方向：把 Codex 的额度、Agent 进度和模型切换放在手边。围绕“看额度 → 看哪个 Agent 需要关注 → 进入任务并切换模型”展示实际使用过程，避免把所有按键堆进首屏。

先邀请少量符合条件的人实际使用，记录他们是否完成首次操作、卡在哪里、是否愿意在下次工作中继续使用。若只是觉得外观有趣，仍不足以证明日常价值。不宣称尚未测量的效率提升，不把 Star 数作为有用的证据。

## 产品入口

| 产品 | 面向谁 | 演示重点 | 到达页面后的主要动作 |
| --- | --- | --- | --- |
| AgentController | 经常使用 Codex、希望通过手柄查看和控制任务的人 | 按本产品支持范围展示任务进度、模型控制与额度相关信息，操作与屏幕结果同框 | 判断是否适合自己，下载并完成首次操作 |
| Micro | 希望随时查看额度和 Agent 进度、快速调节模型的人 | 额度显示、任务状态、一次模型切换；桌面小键盘是载体 | 下载独立桌面版；插件作为次要入口 |
| codex-control | 集成或贡献代码的开发者 | 控制接口、支持范围与固定版本依赖 | 查看接口与构建方式 |

两个产品各自回答具体用途。AgentController 是本仓库的首要内容，Micro 只作为相关选择；组件仓服务开发者。传播效果、硬件门槛与实际使用价值分别观察，不预设哪个产品更受欢迎。

## 内容与渠道

- 演示优先依次展示额度、Agent 进度和模型切换，每个产品使用自己的真实画面与支持范围。首条约 20–40 秒，时长服务于把场景讲清楚；涉及手柄操作时才加入手柄画面。
- 每条只呈现当前包已确认可用的动作，画面与版本一致；设计稿和未来功能单独标注。
- 第一轮面向已有 Codex 用户小范围分享，优先收集使用反馈。后续再从 X、B 站或 V2EX 等已有受众的渠道选择一两个扩大分享。
- 帖子直接链接对应产品 README；下载入口、运行要求与首个操作应能快速找到。
- 可运行的公开包与安装入口准备好后，再考虑 Show HN。按其规则提供可试用的产品，并由作者参与讨论。
- 第二轮围绕真实问题制作短内容：怎样安装、怎样切任务、支持哪些设备。优先修复共同遇到的安装障碍。

## 简要 README 结构

每个产品使用自己的首屏，中文与英文保持同一信息结构。正文目标为约 40–70 行，实际用途、演示和开始使用优先。

1. **名称与一句用途**：围绕额度、Agent 进度与模型调节的实际价值，按该产品能力准确取舍。
2. **一段演示**：一张预览图或短动图，链接完整视频；展示对应发行版。
3. **下载与要求**：一个主要下载入口；Windows、架构、必要运行时、Codex 要求，以及会影响安装的签名/驱动条件。
4. **三步开始**：下载并解压/安装 → 启动并连接目标 → 完成第一个简单操作。源码构建不是普通用户的默认入口。
5. **三个主要用途**：看额度、看 Agent 进度、快速调模型；各用一行说明，并准确标出当前产品/版本的支持范围。
6. **当前边界与帮助**：兼容性、已知限制和反馈链接；macOS 标为计划/未实现，不列为可下载平台。
7. **项目关系与许可证**：另一产品一行互链；开发文档一行；标明 GPL-3.0-only、允许商用及分发时的源码义务，保留第三方项目身份和素材权利说明。

长篇由来、完整键位表、架构、构建与维护说明分别链接到文档。历史 iOS 原型不作为首屏功能或路线图卖点。GitHub Star 可作为末尾次要动作，不作为下载条件。

组件仓 README 面向开发者：职责、两个包、接口示例、固定版本获取、平台限制和许可证，无需产品演示式首屏。

## 发布前应对齐的事实

- 目前公开发行仍为 AgentController 1.2.1 和旧仓 Micro 0.3.10；新 Micro 0.3.15-local.1 仅为本地产物。README 必须明确公开下载与开发分支的区别。
- 独立 Micro 的免虚拟 HID 驱动属性不能直接套用于全部 AgentController 操作。
- Windows/macOS 同仓是维护方向；macOS 暂无可运行版，iOS 暂无产品计划。
- 公开包尚未准备好时不写可下载新版本的承诺，也不使用不存在的新仓链接。
- 额度刷新以实际实现为准，不承诺无延迟；Agent 进度按实际状态展示，不虚构完成百分比；模型调整说明生效范围，不暗示能改变已开始执行的生成。

## 衡量

首要观察首次操作是否成功、安装与操作障碍、是否解决用户的实际需求，以及用户自愿反馈的再次使用情况。先用 Issue 与讨论收集，不为此新增遥测。

次要记录每次分享时间和渠道；按 7 天观察仓库访问、来源、Star 增量和 Release 附件下载增量。下载次数不等于安装成功或独立用户，GitHub 聚合数据也不能精确归因每次转化。

优先检查：用户是否找到正确下载、能否完成首次使用、哪些问题反复出现。准备推广素材之前先保证这条路径可用。
